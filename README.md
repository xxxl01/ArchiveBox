# 归档盒 · ArchiveBox

Windows 本地文件归档工具，基于 **WPF + .NET Framework 4.8 + SQLite**。无需账号或服务器，使用普通磁盘目录存储文件。

## 运行

**.NET Framework 4.8 是主发行版本，不是可选的兼容版本。应用运行不需要 .NET 10。**

- 当前主包为 `ArchiveBox-v0.3.1-win-x64.zip`，面向 64 位 Windows 11，重点适配 Windows 11 21H2（build 22000）。
- Windows 11 通常已包含 .NET Framework 4.8 或兼容的原位更新，无需额外安装现代 .NET Desktop Runtime。
- 解压完整目录后运行 `ArchiveBox.exe`。EXE、`ArchiveBox.exe.config`、DLL 和 SQLite 原生库必须一起保留；请勿与旧版 DLL 混用。
- 普通用户权限即可运行，同一用户会话同时运行一个实例。
- 本项目没有 build 22000 实机；编译目标和旧 API 适配不能替代该具体系统版本的运行验证。

启动失败时，运行程序目录里的 `Diagnose-ArchiveBox.cmd`。它会记录 Windows build、Framework Release、进程输出和退出代码。应用也会记录托管异常，UI 致命异常会显示错误和日志路径后退出。日志在 `%LocalAppData%\ArchiveBox`；不可写时回退到 `%TEMP%\ArchiveBox`。

从旧版升级时，关闭旧程序，将新版解压到新的程序目录即可。数据库和归档文件位置不变，不需要清空数据。旧版 v0.1.0 的 .NET 10 运行包已不再作为主版本。

## 使用

1. 在侧边栏“设置”中选择唯一的归档根目录。已有文件夹可以直接选择；更换根目录不会自动搬移旧文件。
2. 首页是快速文件夹。点击“添加文件夹”，或在浏览页点击“添加到首页”，以后直接点击卡片打开；从首页移除不会删除实际文件夹。
3. 在“浏览文件”中选择文件或文件夹，在右侧目录树选中已有目标目录，然后点击顶部“复制”或“移动”。两种操作都会弹出确认框，确认后直接执行。
4. 新建分类时点击“新建文件夹”，在独立弹窗里输入名称；选择已有目标目录不需要填写任何名称。
5. “归档文件”显示归档目录的真实内容，左边是文件夹，右边是当前文件夹的文件，包含原本就存在的文件。
6. 在左侧选择文件夹，点击“设置文件夹到期”；也可勾选右侧文件，点击“设置文件到期”。这两种设置只在归档文件页提供。
7. 到期时间按最近的上级文件夹规则继承。文件单独设置可以覆盖文件夹；选择“不设到期”也会覆盖上级；选择“继承上级规则”清除覆盖。
8. “即将到期”和“已到期”只扫描相关规则覆盖的范围，没有相关规则时直接返回；结果分批显示，扫描期间可取消、切换页面。到期只提醒，不自动删除；确认后可以移入 Windows 回收站。
9. “任务记录”查看操作结果与失败原因。右侧不再堆放表单，底部也没有固定状态/详情区；操作进度只在进行中显示，结果显示在页面标题下方，不显示浮动提示或路径悬浮提示。

文件列表支持多选、表头排序、文件名/路径搜索和手动刷新。`Ctrl+O` 选择浏览目录，`F5` 刷新。文件夹复制/移动保留内部层级；目录联接和符号链接会被拒绝，避免越界操作。

## 文件操作规则

- 同名默认自动重命名，如 `报告 (1).pdf`，也可选择跳过；不覆盖已有文件或目录。
- 复制先写入目标目录中的专用临时文件，完成后做 SHA-256 校验，再提交正式文件。
- 移动使用“复制 → 校验 → 提交 → 再次核对源文件与归档副本 → 移除源文件”，同盘和跨盘使用同一条流程。这样会比同盘直接改名慢一些。
- 如果源文件已改变、被占用或无权移除，归档副本保留，任务标记为“源文件保留”。请人工核对，不自动再次删除源文件。
- 应用意外退出后，下次启动和刷新会检查未完成任务；恢复流程不会自动删除源文件。离线归档盘的任务等待下次连接。
- 取消操作保留已完成的文件，删除当前任务的临时副本，不自动撤销已完成任务。
- 归档文件在应用外被改动后，内容校验不一致时拒绝回收，避免把新内容直接删掉。此时请在资源管理器中人工核对、处理。
- 回收站使用 Windows Shell，并保留系统确认对话框。网络共享、某些移动磁盘、超出回收站容量的文件可能无法回收；如果系统提示永久删除，请取消。应用不会自动确认这类系统提示，也不提供主动永久删除入口。
- 第一版跳过符号链接、目录联接，路径中的链接也会被拒绝；云盘的占位目录可能因此不可用。请使用实际的本地目录。
- 归档视图读取真实目录，既显示应用归档的文件，也显示原本存在的文件。文件夹到期规则对子目录和新文件生效，文件单独设置优先。
- 不追踪应用外对归档文件的重命名或移动；原路径不可用时显示“文件不可用”。改变归档根目录会保留旧位置的记录，第一版没有整库迁移功能。

## 本地数据与备份

数据库与最近目录记录：`%LocalAppData%\ArchiveBox\archivebox.db`。错误日志在同一目录，最多保留最近 14 个日志文件。归档文件保存在自己选择的真实归档目录里。

应用左下方可以打开本地数据目录。**备份时先关闭应用，再同时备份整个本地数据目录和所有归档根目录**。只备份文件不能恢复预计删除时间；只备份数据库也不能恢复文件。

文件状态保存在 SQLite；每个归档文件保存根路径、相对路径、来源、归档时间、到期时间与内容校验值。时间以 UTC 保存，在界面显示为本地日期；自定义日期按当天结束计算。

## 开发

应用目标为 **.NET Framework 4.8**，核心库目标为 .NET Standard 2.0（由 Framework 4.8 应用加载），测试项目也目标为 Framework 4.8。编译器可以使用现代 C#，不意味着用户运行时需要现代 .NET。

在 Windows 安装 Visual Studio 2022 17.14 或更新版本（“.NET 桌面开发”工作负载，含 MSBuild、Framework 4.8 开发组件，以及构建所需的 SDK）。打开 `ArchiveBox.sln`，或在 PowerShell 中运行：

```powershell
# 编译、运行 Framework 测试、生成唯一的主发行包
./build.ps1

# 对实际发布目录进行窗口初始化、文件列表刷新及视图切换检查
./scripts/smoke-test.ps1
```

输出：`artifacts/ArchiveBox-v0.3.1-win-x64.zip`。程序运行只依赖 Framework 4.8；编译工具不随程序发布。

```text
src/ArchiveBox.App/          Framework 4.8 WPF 界面、MVVM、Windows 集成
src/ArchiveBox.Core/         .NET Standard 2.0 文件操作、数据库、路径检查
tests/ArchiveBox.Core.Tests/ Framework 4.8 测试
scripts/                    启动检查及用户诊断入口
```

核心测试使用独立的 Framework xUnit 宿主和临时目录，回收站测试使用替身，不操作真实回收站。目录联接测试在临时目录中创建并移除 junction。启动检查使用隔离的数据目录，不修改正常使用的数据库；另外用 Windows PowerShell 5.1 检查诊断入口。

GitHub Actions 在 Windows Server 2022、2025 上编译、运行 Framework 测试并检查窗口初始化和交互；没有 Windows 11 21H2 runner，不宣称已经在 build 22000 上实测。只有相应工作流通过后才代表该检查通过。

推送 `v主版本.次版本.修订版本` 标签会触发 Windows 发布流程，只发布 Framework 4.8 主包和 SHA-256 校验文件。Release 标题、说明和文件名使用英文，应用界面保持中文。

## 第一版边界

当前提供首页快速文件夹、目录浏览、唯一归档根目录、多级分类、文件及文件夹复制/移动、到期继承和文件覆盖、任务记录、进度与取消。暂不提供自动刷新、后台定时处理、外部文件重命名规则跟踪或自动分类。
