# 归档盒 · ArchiveBox

Windows 本地文件归档工具，基于 **WPF + .NET 10 + SQLite**。无需账号或服务器，使用普通磁盘目录存储文件。

## 运行

- 支持 Windows 10 / 11，当前打包版本为 x64。
- **standalone 独立版**：解压完整目录，双击 `ArchiveBox.exe`，不需要额外安装 .NET。
- **lite 轻量版**：解压完整目录；先安装微软 **.NET 10 Desktop Runtime x64**，再运行 `ArchiveBox.exe`。
- 请勿只复制 EXE；SQLite 原生库和其他 DLL 需要一起保留。
- 普通用户权限即可运行，同一用户会话同时运行一个实例。

微软运行时下载：https://dotnet.microsoft.com/download/dotnet/10.0 （选择 Windows 的 **.NET Desktop Runtime**，不是仅 .NET Runtime，也不是 ASP.NET Core Runtime）。

## 使用

1. 点击“选择文件夹”打开待整理目录，也可以输入路径后按 Enter。首页会记住上次位置，路径下拉框保存最近 15 个目录。
2. 右侧选择归档根目录，在目录树中选择目标子目录。可以创建多级子目录，例如 `工作/项目 A`。
3. 勾选文件，或用 Ctrl / Shift 多选；选择“复制到归档”或“移动到归档”。文件夹双击进入，第一版不批量归档整个文件夹。
4. 设置“不设置 / 7 天 / 30 天 / 90 天 / 自定义日期”，然后点击“开始归档”。移动需要确认。
5. 在“全部归档”中选择文件，再点击“应用预计删除时间”，可批量延长或取消到期时间。
6. “即将到期”显示未来 7 天内到期的文件，“已到期”显示已经到期的文件。核对后可以批量移入 Windows 回收站。
7. “任务记录”查看归档结果、失败原因，选择失败记录可以重试。重试会新增任务记录，原始历史保留。

**预计删除时间只作用于归档中的文件。复制操作的源文件不会因到期被处理。到期只作提醒，不自动删除，关闭应用后也不会运行定时删除任务。**

列表只显示当前层级的全部文件和子目录，支持文件名或路径搜索、表头排序与手动刷新。快捷键：`Ctrl+O` 选择目录，`F5` 刷新。列表的“修改 / 归档时间”在浏览模式显示修改时间，在归档视图显示归档时间。

## 文件操作规则

- 同名默认自动重命名，如 `报告 (1).pdf`，也可选择跳过；不覆盖已有文件或目录。
- 复制先写入目标目录中的专用临时文件，完成后做 SHA-256 校验，再提交正式文件。
- 移动使用“复制 → 校验 → 提交 → 再次核对源文件与归档副本 → 移除源文件”，同盘和跨盘使用同一条流程。这样会比同盘直接改名慢一些。
- 如果源文件已改变、被占用或无权移除，归档副本保留，任务标记为“源文件保留”。请人工核对，不自动再次删除源文件。
- 应用意外退出后，下次启动和刷新会检查未完成任务；恢复流程不会自动删除源文件。离线归档盘的任务等待下次连接。
- 取消操作保留已完成的文件，删除当前任务的临时副本，不自动撤销已完成任务。
- 归档文件在应用外被改动后，内容校验不一致时拒绝回收，避免把新内容直接删掉。此时请在资源管理器中人工核对、处理。
- 回收站使用 Windows Shell，并保留系统确认对话框。网络共享、某些移动磁盘、超出回收站容量的文件可能无法回收；如果系统提示永久删除，请取消。应用不会自动确认这类系统提示，也不提供主动永久删除入口。
- 第一版跳过符号链接、目录联接，路径中的链接也会被拒绝；云盘的占位目录可能因此不可用。请使用实际的本地目录。
- 归档视图列出应用管理的文件记录；用资源管理器直接放入归档目录的文件不会自动获得到期记录，可以从浏览页选择后归档到其他子目录。
- 不追踪应用外对归档文件的重命名或移动；原路径不可用时显示“文件不可用”。改变归档根目录会保留旧位置的记录，第一版没有整库迁移功能。

## 本地数据与备份

数据库与最近目录记录：`%LocalAppData%\ArchiveBox\archivebox.db`。错误日志在同一目录，最多保留最近 14 个日志文件。归档文件保存在自己选择的真实归档目录里。

应用左下方可以打开本地数据目录。**备份时先关闭应用，再同时备份整个本地数据目录和所有归档根目录**。只备份文件不能恢复预计删除时间；只备份数据库也不能恢复文件。

文件状态保存在 SQLite；每个归档文件保存根路径、相对路径、来源、归档时间、到期时间与内容校验值。时间以 UTC 保存，在界面显示为本地日期；自定义日期按当天结束计算。

## 开发

安装 .NET 10 SDK，用 Visual Studio 2026 或支持 .NET 10 的 IDE 打开 `ArchiveBox.sln`。

```powershell
dotnet build ArchiveBox.sln -c Release
dotnet test tests/ArchiveBox.Core.Tests/ArchiveBox.Core.Tests.csproj -c Release
dotnet run --project src/ArchiveBox.App

# 轻量包（依赖 Desktop Runtime）
./build.ps1

# 独立包（自带 Desktop Runtime）
./build.ps1 -SelfContained

# Windows ARM64 独立包
./build.ps1 -Runtime win-arm64 -SelfContained
```

Windows App 可以在 Linux 上使用 `EnableWindowsTargeting` 交叉编译；WPF 窗口及 Windows 回收站集成仍需在 Windows 实机验证。

```text
src/ArchiveBox.App/         WPF 界面、MVVM、Windows 集成
src/ArchiveBox.Core/        文件操作、数据库、路径检查
tests/ArchiveBox.Core.Tests/ 文件操作与恢复测试
```

核心测试使用临时目录，回收站测试使用替身，不操作真实回收站。GitHub Actions 提供 Windows 构建、核心测试和窗口启动检查；只有工作流实际运行后才代表该检查通过。

## 第一版边界

当前提供目录浏览、最近目录、多级归档、复制/移动、到期管理、任务记录、进度与取消。暂不提供自动刷新、后台定时处理、外部文件移动追踪、整目录归档或自动分类。
